MATHOS UAV SYSTEM
MAINTENANCE PAGES SPECIFICATION
================================

PURPOSE
-------
This document defines the planned maintenance pages for every ESP32 role in the MATHOS UAV system.

Maintenance mode is entered only when:
- MASTER switch is OFF.
- MAINTENANCE switch is ON.
- The device is rebooted.

While maintenance mode is active:
- Normal control tasks remain disabled.
- Arming is unavailable.
- Flight-control output is disabled.
- Configuration changes are allowed only through the maintenance interface.
- A reboot is required before returning to normal operation.


SYSTEM ARCHITECTURE
===================

Primary aircraft path:
Flight Controller
    -> Airborne Gateway ESP32
    -> Main RC ESP32

Secondary remote-telemetry path:
Main RC ESP32
    -> RC Telemetry-Relay ESP32
    -> Remote Ground Gateway ESP32
    -> API / Monitoring Server

ESP32 roles:
1. Main RC ESP32
2. Airborne Gateway ESP32
3. RC Telemetry-Relay ESP32
4. Remote Ground Gateway ESP32


SHARED MAINTENANCE ENGINE
=========================

The shared mathos_maintenance component should provide:
- Maintenance SoftAP startup.
- HTTP server startup.
- Role detection.
- Safe HTML generation.
- HTML escaping.
- URL/form decoding.
- Request body size limits.
- Configuration validation.
- NVS save, commit, read-back and verification.
- Configuration versioning.
- CRC integrity checking.
- Safe-default loading.
- Role-specific route registration.
- Maintenance status information.
- Control-task-disabled safety state.

The shared component should not force all devices to use the same page or configuration structure.

Recommended configuration structures:
- mathos_maintenance_common_config_t
- mathos_maintenance_rc_config_t
- mathos_maintenance_gateway_config_t
- mathos_maintenance_relay_config_t
- mathos_maintenance_ground_gateway_config_t

Recommended NVS namespaces or keys:
- mathos_common
- mathos_rc
- mathos_air_gw
- mathos_relay
- mathos_ground_gw


1. MAIN RC MAINTENANCE PAGE
===========================

Purpose
-------
Configure and test the physical remote controller, the primary secure aircraft link, and the local telemetry output to the RC Telemetry-Relay ESP32.

--------------------------------

- Firmware version.
- Build identifier.
- Maintenance mode active.
- Local maintenance IP address.
- MASTER switch state.
- MAINTENANCE switch state.
- Control tasks disabled.
- Current configuration source: Safe defaults or Saved configuration.
- Free heap.
- Reset reason.
- Uptime.

B. Controller calibration
-------------------------
Editable or guided calibration controls:
- Roll joystick minimum, centre and maximum.
- Pitch joystick minimum, centre and maximum.
- Throttle minimum, centre when applicable, and maximum.
- Yaw minimum, centre and maximum.
- Dead zone per axis.
- Axis inversion per axis.
- Input filtering level.
- Calibration wizard.
- Live raw ADC display.
- Live normalized channel display.
- Save calibration.
- Restore previous calibration.
- Restore safe defaults.

C. Switch and button diagnostics
--------------------------------
Read-only live tests:
- MASTER switch.
- ARM permission switch.
- MAINTENANCE switch.
- OPTIC/RF selector.
- ARM button.
- DISARM button.
- FAILSAFE button.
- RECOVER button.
- Auxiliary switches.
- Button press counters.
- Debounce status.
- Stuck-input warning.

D. Primary aircraft-link security
---------------------------------
The primary secure link is:

Main RC ESP32
    <-> Airborne Gateway ESP32

Configuration and status:
- RC device ID.
- Expected airborne gateway peer ID.
- Current key ID.
- Primary secure key status: Configured or Not configured.
- New 256-bit root key.
- Confirm new 256-bit root key.
- Key rotation command.
- Pairing status.
- Last authenticated packet age.
- Last authenticated peer ID.
- Authentication success counter.
- Authentication failure counter.
- Replay rejection counter.
- Duplicate packet counter.
- Current session status.
- Clear pairing action with strong confirmation.

Key-entry rules:
- The root key is 32 random bytes.
- Hexadecimal entry format uses 64 hex characters.
- The key field uses <input type="password">.
- The existing key is never displayed.
- The existing key is never returned to the browser.
- The existing key is never printed in logs.
- An empty submitted key means keep the existing key.
- Clearing the key requires a separate explicit action.
- New key and confirmation fields must match.
- Invalid length or non-hex characters are rejected.
- The key is stored only after NVS write and read-back verification.
- The new key becomes active only after reboot.
- Nonce counters are never manually configured by the user.
- Directional and session keys are derived internally from the root key.

5. KEY SEPARATION
=================

At least two independent secure roots are required.

Primary aircraft-control and telemetry link:
- Main RC ESP32 <-> Airborne Gateway ESP32
- Root key A

Secondary remote-monitoring link:
- RC Telemetry-Relay ESP32 <-> Remote Ground Gateway ESP32
- Root key B

Optional local RC-to-relay link:
- Main RC ESP32 <-> RC Telemetry-Relay ESP32
- Root key C

Rules:
- Root key A, B and C must be different.
- API tokens are not encryption root keys.
- Wi-Fi passwords are not encryption root keys.
- Maintenance AP passwords are not link root keys.
- Directional session keys are derived internally.
- Nonces and anti-replay counters are managed internally.
- Root keys are never transmitted in normal operation.
- Root keys are never displayed after provisioning.

Required controls:
- Physical MAINTENANCE switch active.
- MASTER switch off.
- Normal control tasks disabled.

- Maintenance AP enabled only in maintenance mode.
- Role-specific routes only.

Sensitive information that must never appear in logs:

Phase 4: RC Telemetry Relay

- Recovery and factory-reset procedure.


8. CURRENT DECISIONS
====================

Confirmed:
- The Main RC ESP32 does not send telemetry directly to the internet.
- The Main RC sends selected telemetry to a second ESP32.
- The RC Telemetry-Relay ESP32 sends telemetry over a separate RF link.
- The Remote Ground Gateway ESP32 receives that telemetry.
- The Remote Ground Gateway sends telemetry to the API/server.
- Internet Wi-Fi credentials belong to the Remote Ground Gateway.
- Primary and secondary RF links use different root keys.
- Maintenance pages are role-specific.
- RC calibration controls must never appear on the Airborne Gateway.
- Gateway FC/MAVLink controls must never appear on the RC.
- Sensitive keys are provisioned only in maintenance mode.
- Existing secrets are never shown after provisioning.
